# 批量验证运行器

`tools/verify_batch.py` 是可在公司或家里环境复用的验收入口。它不会修改
拆字算法，只负责固定字集、隔离结果、控制并发、断点续跑和记录环境指纹。

## 准备

项目根目录需要包含：

```text
Fonts/
makemeahanzi-master/graphics.txt
makemeahanzi-master/dictionary.txt
hanzi_chaizi-master/
```

在 Windows PowerShell 中进入项目目录后直接运行：

```powershell
python -X utf8 tools/verify_batch.py --preset sample --bench
python -X utf8 tools/verify_batch.py --preset cross
python -X utf8 tools/verify_batch.py --preset full
```

如果项目目录不同，用 `--root` 指定；如果只想验证某个字体，用 `--fonts`：

```powershell
python -X utf8 tools/verify_batch.py `
  --root D:\07_chcharapart `
  --preset full `
  --fonts HarmonyOS_Sans_SC.ttf `
  --jobs 8
```

## 预设含义

| 预设 | 字集 | 默认字体 | 用途 |
|---|---:|---|---|
| `sample` | 全库每 10 字取 1 | HarmonyOS SC | 每轮算法改动的主门 |
| `cross` | 全库每 30 字取 1 | simhei、Noto SC | 泛化回归 |
| `full` | 全库 | HarmonyOS SC | 里程碑验收 |

每次运行都会生成独立目录：

```text
verifyOut/runs/YYYYMMDD-HHMMSS-<preset>/
  chars.txt       本次实际字集
  manifest.json   源码、字体、机器、并发和耗时指纹
  <font>.jsonl    逐字结果
  summary.json    失败分类汇总
  report.html     浏览器报告
```

默认 `--jobs` 是 `min(8, CPU-2)`，家用 Windows 机器可直接复用。脚本在
worker 启动前先预热一次 B 库，避免首次运行时每个 worker 重复建库；已有
算法签名有效的库会按现有机制复用。需要从头生成结果时使用 `--no-resume`。

## 结果口径

脚本保留 `strokelab.verify` 的既有失败码和阈值。`manifest.json` 中的
`charSha256`、源码指纹和字体文件信息用于确认两台机器是否测的是同一批
输入。结果目录不要和另一轮运行合并，避免旧 jsonl 污染 summary。

## 协作验证的独立完整性检查

`verify_batch.py` 完成运行不等于验收通过，逐字失败不会直接令它返回非零。
使用 `tools/check_protocol_results.py` 对完整的同字集结果进行检查：

```powershell
python -X utf8 tools/check_protocol_results.py <baseline.jsonl> <current.jsonl> --chars-file <chars.txt> --min-passed 920 --out <comparison.json>
```

它会拒绝重复行、漏字、多字、缺字状态改变，并检查通过数、ERROR/UNION 与
compQuota。`--min-passed` 应取当前移交单约定值，示例的 920 对应 f553ce7 的
957 个可测抽样字，不是所有批次的固定阈值。跨字体门可用 `--max-net-loss 2`
表达协议允许的噪声范围。

输出同时列出修复、回退、失败码迁移及软指标总和。字段
`integrityAndCountGatePassed=true` **只表示完整性和聚合数字门通过**，不代替
逐字回退审查；净改善也可能同时包含新回退，必须结合 `regressions` 与
`migrations` 交接。

不要把不同机器的历史结果差异直接归因为代码：先固定 Git 版本、字集、
字体、输入数据、缓存与依赖版本做同机 A/B。独立快照的参考记录见
`verifyOut/acceptance-f553ce7/identity.json`。
