# 批量验证运行器

`tools/verify_batch.py` 是可在公司或家里环境复用的验收入口。它不会修改
拆字算法，只负责固定字集、隔离结果、控制并发、断点续跑和记录环境指纹。

## 准备

项目根目录需要包含：

```text
Fonts/
makemeahanzi-master/graphics.txt
makemeahanzi-master/dictionary.txt
hanzi_chaizi-master/
```

在 Windows PowerShell 中进入项目目录后直接运行：

```powershell
python -X utf8 tools/verify_batch.py --preset sample --bench
python -X utf8 tools/verify_batch.py --preset cross
python -X utf8 tools/verify_batch.py --preset full
```

如果项目目录不同，用 `--root` 指定；如果只想验证某个字体，用 `--fonts`：

```powershell
python -X utf8 tools/verify_batch.py `
  --root D:\07_chcharapart `
  --preset full `
  --fonts HarmonyOS_Sans_SC.ttf `
  --jobs 8
```

## 预设含义

| 预设 | 字集 | 默认字体 | 用途 |
|---|---:|---|---|
| `sample` | 全库每 10 字取 1 | HarmonyOS SC | 每轮算法改动的主门 |
| `cross` | 全库每 30 字取 1 | simhei、Noto SC | 泛化回归 |
| `full` | 全库 | HarmonyOS SC | 里程碑验收 |

每次运行都会生成独立目录：

```text
verifyOut/runs/YYYYMMDD-HHMMSS-<preset>/
  chars.txt       本次实际字集
  manifest.json   源码、字体、机器、并发和耗时指纹
  <font>.jsonl    逐字结果
  summary.json    失败分类汇总
  report.html     浏览器报告
```

默认 `--jobs` 是 `min(8, CPU-2)`，家用 Windows 机器可直接复用。脚本在
worker 启动前先预热一次 B 库，避免首次运行时每个 worker 重复建库；已有
算法签名有效的库会按现有机制复用。需要从头生成结果时使用 `--no-resume`。

## 结果口径

脚本保留 `strokelab.verify` 的既有失败码和阈值。`manifest.json` 中的
`charSha256`、源码指纹和字体文件信息用于确认两台机器是否测的是同一批
输入。结果目录不要和另一轮运行合并，避免旧 jsonl 污染 summary。

## 协作验证的独立完整性检查

`verify_batch.py` 完成运行不等于验收通过，逐字失败不会直接令它返回非零。
使用 `tools/check_protocol_results.py` 对完整的同字集结果进行检查：

```powershell
python -X utf8 tools/check_protocol_results.py <baseline.jsonl> <current.jsonl> --chars-file <chars.txt> --min-passed 920 --out <comparison.json>
```

它会拒绝重复行、漏字、多字、缺字状态改变，并检查通过数、ERROR/UNION 与
compQuota。`--min-passed` 应取当前移交单约定值，示例的 920 对应 f553ce7 的
957 个可测抽样字，不是所有批次的固定阈值。跨字体门可用 `--max-net-loss 2`
表达协议允许的噪声范围。

输出同时列出修复、回退、失败码迁移及软指标总和。字段
`integrityAndCountGatePassed=true` **只表示完整性和聚合数字门通过**，不代替
逐字回退审查；净改善也可能同时包含新回退，必须结合 `regressions` 与
`migrations` 交接。

不要把不同机器的历史结果差异直接归因为代码：先固定 Git 版本、字集、
字体、输入数据、缓存与依赖版本做同机 A/B。独立快照的参考记录见
`verifyOut/acceptance-f553ce7/identity.json`。

## 一键门禁(gate_report + run_tests.bat)

`tools/gate_report.py` 把一次完整门禁(bench / parity / verify_batch 各预设 /
trace 胜率表)编排成一次运行,聚合为单一 `report.json` —— 家里先上代码,
公司好电脑跑数据,跑完把 `report.json` 交回主会话解析即可,无需人工汇总。

仓库根的 `run_tests.bat` 双击可跑(默认 std),或在命令行:

```bat
run_tests.bat quick   rem bench + parity + sample           (~25 分钟)
run_tests.bat std     rem quick + cross + coverage          (默认)
run_tests.bat full    rem std + 全量 + trace 胜率表          (数小时)
run_tests.bat quick --resume verifyOut\gateReport\<目录>  rem 断点续跑
```

注意:`run_tests.bat` 本体必须保持纯 ASCII——cp936 控制台下 cmd 对含
中文注释的 UTF-8 批处理会吞行错切(本机实测 `chcp 65001` 也救不回),
中文输出全部由 gate_report.py 负责,bat 里的 `chcp 65001` 只为正确显示
python 的 UTF-8 输出。

等价的直接调用:`python -X utf8 tools/gate_report.py --suite quick`
(可加 `--jobs N` 覆盖 worker 数)。退出码:**0=所有硬门 pass/skip,
1=任一硬门 fail(含步骤异常),2=参数错误**;bat 透传该退出码。

产物 `verifyOut/gateReport/<时间戳>-<git短rev>/`:`report.json`(契约见下)、
`report.md`(人读版)、`<步>.log`(各步原始输出)、`sample/` 等子目录
(各 verify 步的独立 run 目录)。`verifyOut/gateReport/latest.txt` 始终指向
最近一次报告目录。每步完成即落盘 report.json,中断后用
`--resume <目录>` 跳过已完成步;未完成的 verify 步复用同一 run 目录,借
verify_batch 既有 jsonl 机制续跑。

### report.json 字段契约(contractVersion=1,主会话解析依据)

| 字段 | 类型 | 含义 |
|---|---|---|
| `contractVersion` | int | 契约版本,字段变更时递增 |
| `rev` / `revFull` / `dirty` | str/str/bool | git 短/全 rev;dirty=有未提交改动(不含 untracked) |
| `createdAt` / `resumedAt` | str | ISO 时间戳(resumedAt 仅续跑时出现) |
| `suite` | str | quick / std / full |
| `gateDir` | str | 报告目录绝对路径 |
| `env.python/platform/machine` | str | 运行环境 |
| `env.algorithmSha256` | str | strokelab 算法源码指纹(与 verify_batch manifest 同口径,跨机对版) |
| `env.fonts.{文件名}` | obj | `size/mtimeNs/sha256` 字体指纹 |
| `steps.{步}.status` | str | `pending/skipped/done/error`(done 表示步骤跑完,不代表门通过) |
| `steps.{步}.exitCode/elapsedSeconds/log/runDir` | — | 步骤执行信息(路径相对报告目录或绝对) |
| `gates.bench` | obj | `{cases, broken}`,broken=verified 回退/错误数 |
| `gates.parity` | obj | `{cases, mismatch}` |
| `gates.sample/cross/coverage/full.{字体}` | obj | `{tested, passed, rate}`(rate=百分数) |
| `baselines` | obj | 硬编码基线表 + `crossNoiseChars`(跨字体噪声容差,字) |
| `verdicts.{门}.verdict` | str | `pass/fail/skip` |
| `verdicts.{门}.hard` | bool | 是否参与退出码(full 为软门 false) |
| `verdicts.{门}.delta` 或 `.fonts.{字体}.deltaPp/deltaPassed` | num | 与基线差值(百分点/字数;tested 漂移时 deltaPassed=null 并附 note) |
| `verdicts.overall` | str | `pass/fail`,与退出码 0/1 对应 |
| `failLists.{步}.{字体}` | str | 失败字串(超 5000 字截断并标注总数) |
| `softMetrics.{步}.{字体}` | obj | `compQuota/compOut/orderX/reclass/tested` 逐字体求和(协议趋势项,compQuota 应恒 0) |

### 判定规则(与协作验证协议对齐)

- **bench**:`broken == 0`;**parity**:`mismatch == 0`,
  `verifyOut/parity_base.json` 不存在时记 skip(不算失败)。
- **sample / coverage**(硬门,零容差):tested 与基线一致时按
  `passed ≥ 基线 passed`;字集/字体漂移时退化为 `rate ≥ 基线 rate` 并附 note。
- **cross**(硬门):每字体允许 ±2 字协议噪声,`passed ≥ 基线 passed − 2`;
  tested 漂移时按通过率减去换算容差判。
- **full**(软门):`rate ≥ 95.5`(移交单#5 外推预期),不影响退出码。
- 基线表硬编码在 `tools/gate_report.py` 的 `BASELINES`(2026-09-14 口径:
  sample958=97.39 / simhei=90.60 / Noto=77.19 / simsun=87.15 /
  coverage=380/385)。协议规定升门需两侧同意:改基线必须在提交信息显式
  声明,并同步本表。
- 主会话解析建议:先看 `verdicts.overall`;fail 时按 `verdicts.{门}` 的
  差值定位,再取 `failLists` 与上一基线 run 的 jsonl 跑
  `tools/diff_runs.py` 逐字归因。
