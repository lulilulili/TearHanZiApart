# 汉字笔画拆分下一步计划

## 当前基线

- 鸿蒙 SC 可测 9,570 字，通过 8,690 字，通过率 90.80%。
- 当前工作树的布尔收口、轴向守卫和退化笔画救济修复已通过 4 个单元测试。
- `永、汉、国、爱` 的最终路径复算均为覆盖 100%、溢出 0%。
- 门框样本的 SPLIT 已明显减少，但 `閃、閏` 暴露出残余 TYPE/AREA 问题。

## 第一阶段：冻结并完成可重复验证

1. 使用串行 `reverify.py` 完成 1,646 个 SC 失败字的当前版本复核。
2. 完成 800 个原通过字回归抽样，确认没有新增硬性告警。
3. 对比基线与当前结果，记录修复、回退、缺字和 ERROR/UNION 变化；不修改校验阈值。
4. 将 SC 结果、命令、源码和字体指纹写入验收文档。

## 第二阶段：降低 TYPE/AREA 的共同误报

1. AREA 改用原字形总面积乘楷体逐笔占比计算期望值，避免合法重叠膨胀总面积后连带压低其它笔。
2. 对过大和过小笔分别做定向回迁，保留并集恒等和连通性约束。
3. TYPE 同时参考最终轮廓方向和逐笔中轴方向；只有两者都偏离楷体参照轴时才触发硬告警。
4. 优先验证“一、糹、口、隹、艹、鸟”等高频部件，并用原通过字做回归。

## 第三阶段：处理部件级归属与复合笔画语义

1. 对门框、鸟、隹等部件建立最小失败集，按部件结构修复，不为单字增加特例。
2. 增加复合笔画分段归属指标，识别“整笔完整但内部横/竖段分错”的情况。
3. 保持 COUNT、SPLIT、UNION、ERROR 为硬门；软指标只用于定位和趋势分析。

## 第四阶段：扩展字体回归

1. SC 收口后续跑 TC。
2. 再跑鸿蒙以外的印刷体和手写体，分别统计 OVERLAP 与连笔场景。
3. 保存每种字体的汇总、失败清单和典型字可视化，避免不同算法版本混用结果。

## 验收门槛

- 不新增 ERROR 或 UNION；并集覆盖和溢出保持原阈值。
- 原通过字不得出现新增硬性告警。
- 失败字的净改善必须同时检查回退类别、连通性、面积和逐笔位置。
- 所有结论以当前源码重新生成的逐字结果为准。
