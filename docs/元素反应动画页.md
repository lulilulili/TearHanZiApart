# 元素反应动画页

入口：`viewer/elementalFx.html`。该页是独立的前端消费端，不修改拆字算法、
字体库或校验规则。页面加载时只读取字体清单；用户点击“生成反应场”后，才按
不同汉字串行受控地请求 `/api/decompose`（并发上限 2），标点不请求拆解。

## 模块边界

- `elementRules.js`：部件、强关联字和属性颜色。雨部不直接等于触电，目前
  “雷、電/电、霆”通过强关联字表获得触电属性。
- `reactionRules.js`：属性组合、优先级、反应名称和派生状态。
- `effectPlugins.js`：属性与反应的视觉插件，只操作字卡和粒子层。
- `elementalEngine.js`：获取逐笔路径、编排语段、混色、传播与挂载插件。

新增属性时，在 `ElementalRules.attributes` 登记语义映射，并用
`registerAttribute()` 添加视觉插件。新增反应时调用 `ElementalReactions.register()`，
再用 `registerReaction()` 绑定视觉表现；主编排器无需修改。

## 当前传播口径

核心字强度为 1，相邻一个字符获得 0.32 强度的同色与同属性效果。风属性自身
影响到两字范围；风左右一字内出现的非结晶属性，会以风为中心传播到两字范围。
结晶与扩散按需求不反应，也不由风携带。

直接反应发生在同字多属性或相邻核心字之间。潮湿×生长先产生晶核；晶核相邻
触电字时再派生连锁爆炸。规则日志保留“冰×草”和“结晶×扩散”的不反应记录，
便于演示时解释。

## 审计隔离

本功能只新增 `viewer/`、本说明和一个 Node 规则测试。开发及静态测试不启动
本地服务、不调用拆解 API，因此不会与后台 `tools/audit_accuracy.py` 争用字体
对象或改写 `verifyOut/accuracy/`。用户实际打开页面并生成场景时会产生拆解
计算，建议全库审计结束后再做大段文字演示。
