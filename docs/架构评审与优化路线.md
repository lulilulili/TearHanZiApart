## C库部件模板层评估结论（第6项，2026-09-13）

评估性原型已落地（**默认关**）：`fonthub.buildLibraryC`（五高频旁 氵扌亻口木
× 载体字实拆槽位骨架，`.blibCache/<font>.clib.json` 缓存键含算法签名）+
`dbuild` 注入（一级结构槽位按 radicals.json variants 等价匹配，"载体槽位
实测内容bbox → 目标楷体槽位bbox → affine"放置，逐笔 `_medianDeviation`
≤0.25 守卫回退 B 路径）。开关 `CLIB_ENABLE`（包属性；环境变量
`STROKELAB_CLIB=1` 供 spawn worker 继承）。评估工具 `tools/eval_clib.py`，
数据归档 `verifyOut/clib_eval/`。

载体（鸿蒙）：氵@氾、扌@扎、亻@亿、口@卟、木@未；ZCOOL 两款氵自适应改选
汀（按字体缺字回退）。

| 指标（鸿蒙，五旁各前20成员字=100字） | 关 | 开 |
|---|---|---|
| a 槽位切割路径组内一致性（shapeDescriptor 两两均值） | 83.56 | **83.56（持平）** |
| b verifyChar 通过 | 99/100 | 99/100（0 翻转） |
| c D构建段均耗时 | 5.2ms/字 | 4.2ms/字（−20%，占全程 <0.2%） |
| d coverage preset | 380/385 | **380/385（失败集同为 几戶首龠黽）** |

核心发现：C 命中 223/300 槽位笔（守卫拒 77），但**终态几何仅 1/100 字
改变**（朵，仍通过）——归属迭代/精调/切割由实际墨形主导，B/楷体初始化
与 C 初始化收敛到同一盆地，一致性收益被结构性洗掉；c 的墙钟差在配对采样
偏置内，只认 D构建段的 ~1ms/字。bench 开C 0破坏（verified 门）；
unverified 例里风格化字体终态确实改变且方向混杂（快乐体 中/日 IoU 升、
小薇 日/林 降；⿻口丨/⿴口一 使 中/日 也命中口条目——注入按 IDS 一级
children 匹配，不限 radical 字段）。

**裁定：收益不足，不推荐开启；CLIB_ENABLE 保持 False 提交**（关闭时逐位
零影响，parity 34/34 复验）。残余价值线索：D 初始只在 B 库贫血的风格化
字体上真正左右终局——将来若要救 ZCOOL/手写体档位，C库+逐笔守卫是现成
起点，届时应以风格化字体为评估集重开本项。本轮技术教训已录注释：映射源
bbox 必须用槽位**实测内容** bbox，用楷体名义槽位 bbox 会把载体字体相对
楷体的布局偏移二次记账（载体字对自己注入都过不了守卫：卟三笔 dev
0.33/0.43/1.42）。
