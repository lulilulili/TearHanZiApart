# 协作验证协议（Claude 设计/落地 × Codex 验证）

> 目的：两个代理并行工作时，验收口径唯一、交接零歧义。本文是双方共同契约，
> 修改需在提交信息中显式声明。

## 角色分工

- **Claude**：失败聚类→根因诊断→算法设计→代码落地→自冒烟（回归字集）→提交。
  每个提交自带：改动动机、机制描述、自测数字（抽样/回归集/bench）。
- **Codex**：独立验证与对抗审查。跑完整验收门、复核提交声明的数字、
  diff 审查（边界条件/守卫缺失/与既有仲裁的交互）、跨字体泛化抽查。
  发现回归→在 docs/下一步计划.md 记录字例与码，不直接改算法主干
  （可修明显笔误，需在提交信息标注"验证侧修复"）。

## 验收门（Codex 执行的标准命令）

```bash
# 1. 鸿蒙 958 抽样（主门，字集固定在 verifyOut/sampleChars.txt，每10字取1）
python -X utf8 -m strokelab.verify --root D:/07_chcharapart \
  --fonts HarmonyOS_Sans_SC.ttf --chars <sampleChars.txt内容> --jobs 8 --no-resume
# 通过率不得低于上一提交声明值；失败码分布随提交信息核对

# 2. 难例基准零破坏门
python -X utf8 -m strokelab.bench --root D:/07_chcharapart --check
# "破坏(verified 回退/错误)" 必须为 0

# 3. 跨字体泛化抽查（simhei/Noto 320字，字集 verifyOut/sampleChars30.txt）
# 允许噪声级波动（±2字），系统性下跌(>5字)即回归

# 4. 全量（里程碑时）：9574字，结果入库 verifyOut/
```

- 提交信息必须含：根因（字例+数据）、机制、门控条件、自测数字。
- 回归字集（Claude 自冒烟最小集，Codex 可扩展）：
  磷爱威質醌好吃吗吓中永国水她根狗奶姑目日亨勤厚壮妆博銲肝肽膃

  残余靶单）、orderX、reclass——升门决策需两侧同意。

  数据文件谁跑谁提交；docs/ 双侧可写。
